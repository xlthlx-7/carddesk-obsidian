# 0.4.0 聊天与关联卡片操作说明

这是开发分支上的首版 Codex 聊天闭环。现有渐进阅读布局、展开/收起和路径命令保持不变。

## 准备

1. 在本机安装并登录 Codex CLI。插件不提供登录页面，也不存储新的 API Key。
2. 找到可执行文件绝对路径：macOS/Linux 终端运行 `command -v codex`，Windows 用 `where codex`。不要输入带参数的整条命令。
3. Obsidian 设置 → 接页 Carddesk，填写可执行文件路径，模型可留空，指定新卡目录，点击“保存配置”。
4. 本机验证版本为 Codex CLI `0.169.0-alpha.11.1`，使用 app-server 的 stdio JSON 协议。其他版本未承诺兼容；需要支持 app-server、当前启动选项和对应消息结构。

聊天复用本地 Codex 登录；每次请求使用临时目录、临时线程，复用 auth.json 的符号链接，不复制凭据，不加载用户 config.toml、其自定义提供商、MCP、插件或钩子。不支持仅依赖这些配置的登录/代理场景；若本机使用非文件凭据存储，需要另行验证。Windows 的符号链接权限也尚未验证。

**模型通常在远端运行。** 点击发送或整理草稿，会将选中的正文、问题和历史对话交给 Codex 的模型服务，按其账户规则消耗额度。阅读笔记不需要 CLI、联网或模型；聊天需要可用的 Codex 登录和模型连接。插件不自动读取全库、不自动检索或运行命令。

## 提问

1. 打开普通 Markdown 笔记，或在接页中聚焦当前卡片。
2. 命令面板执行“向 Agent 提问当前卡片”，右侧打开聊天面板。点击不同卡片的“与 Agent 讨论”或对不同卡执行提问命令，默认新建独立会话；同卡再次点击继续当前会话。也可用“打开 Agent 聊天”继续既有会话。
3. 点击输入区上方的“附带卡片”，默认只勾选当前卡。可从已展开的阅读卡片中额外选择，最多 8 张，并预览正文。每次发送时读取当前选中文件；同一会话的历史问题与当时附带的正文也会随请求发送。
4. 输入问题，点击发送或按 Enter；Shift+Enter 换行，也保留 Cmd/Ctrl+Enter。中文输入法选字时的 Enter 不发送。回复逐步出现；点击停止可中断。失败/中断的最后一条可重试，重试会替换这次未完成的回复。
5. 从会话下拉列表可以切回旧讨论。新对话隔离聊天历史；删除当前对话需确认，只删除聊天记录，不删除已经创建的卡片。

不勾选任何卡片也能普通聊天，但该回复无法直接关联到提问卡。要改变上下文，从阅读视图再次执行提问命令；进行中的请求要先停止。

## 转为关联卡片

1. 在一条完整回复下点击“整理为关联卡片”。
2. 在文本框保留有价值的部分，点击“整理为卡片草稿”。这是第二次模型请求，不会写入笔记。
3. 预览新卡标题、正文、目标文件和原卡末尾将追加的自然语言内链；可编辑标题、正文与链接文字。修改后需重新预览。
4. 点击“确认创建卡片并关联”。插件创建普通 Markdown 文件，在提问卡末尾追加内链；不自动插入任意段落，也不改其他旧卡。
5. 回到接页，点击新内链原地展开。展开、收起、返回上层、命名保存与恢复沿用原逻辑。

新卡带 card_id、会话与消息标识、`carddesk_origin: conversation`、`verification_status: unverified`，正文明确标记“对话补充，待核对”。source_path 指向提问卡，source_locator 明确写“对话补充，非原文证据”，不宣称提问卡的原始来源证明了新结论。它可参与现有文件协议，首版不自动创建批量包 manifest。

文件名用消息 UUID 保持重试身份稳定，正文一级标题是可编辑的人类可读标题。当前不提供同一回复反复生成多张卡或自动拆分多卡。

## 冲突与恢复

- 原卡在预览后变化：拒绝加链，重新预览最新原卡再确认。
- 目标已有不同内容：不覆盖；可打开现有卡手动核对，不能靠重复确认覆盖它。
- 新卡创建后加链失败：保留新卡并显示路径；不要重复换目录生成，重新预览后用相同草稿重试。跨文件操作不具备全局事务。
- 同一草稿重复确认不会重复追加链接；用户修改已有关联入口后，会提示手工核对。
- 原卡移动/删除：不会猜测目标。请重新从实际卡片提问；本版不自动迁移历史聊天中的路径。
- 关闭聊天视图会停止请求，已收到的部分回复保留为中断，后续不会作为完整回答重放。

## 保存、限额与升级

聊天、配置和阅读路径共用 `.obsidian/plugins/carddesk/data.json` 的串行写入。聊天约每秒保存已收到的内容，完成/停止时再次保存；突然崩溃仍可能损失最近一小段未写入内容。正常退出重启可恢复会话与状态，使用本地历史重建新的临时 Codex 请求，不恢复厂商远端 thread。

最多 20 个会话、每会话 80 条消息、单问题 10000 字符、单回复 40000 字符、单附带卡片 60000 字符；单次重放最多 160000 字符，聊天数据总计最多约 2000000 个 JSON 字符。超过限制明确报错，不静默截断。完整回答渲染 Markdown 标题、强调、列表和代码块；生成中的回答仍以文本流显示。模型输出的 HTML 不执行，图片和笔记嵌入不自动加载；保存的原始回答不变。

升级前备份 Vault 和 data.json。0.3.4 的阅读状态可读取，阅读快照格式仍为 v1。**降回 0.3.4 会忽略聊天字段，并在保存时移除它们**，因此回退前另存 0.4.0 的 data.json；旧版阅读仍可使用。未知或损坏的保存数据继续阻止覆盖，不会自动清空。

私有聊天、实际 executable 路径、登录文件和测试库状态不进入源码或发布包。不要把实际 data.json 提交到 Git。

## 卡片右上角操作与元信息

每张接页卡片右上角使用铅笔（编辑）和对话（与 Agent 讨论）图标；子卡另有返回上层与收起图标。悬停可查看说明，键盘聚焦也可操作。编辑会在**这张卡片内部**切换为完整 Markdown 文本框，顶部属性与正文都可修改；点击编辑区上方的“完成”后原地恢复阅读，分支保留，不另开标签页。点击“取消”放弃本次草稿。“与 Agent 讨论”选中按钮所在的卡片，默认只附带它，可进一步选择其他展开卡片。不会因为另一个分支拥有阅读焦点而改用另一张卡。

顶部 YAML 属性（包括 sources/raw/updated）在接页阅读中隐藏；原文件内容完整保留，Agent 仍可读取。为兼容旧卡，标题后完整连续的 `> Sources: ...`、`> Raw: ...`、`> Updated: YYYY-MM-DD` 三行也只在阅读呈现中隐藏。普通引用、正文日期和段落不会被隐藏。本规则仅作用于接页阅读，不修改 Obsidian 全局属性设置。

新聊天卡片把 sources、raw、updated 放在顶部，继续保留 card_id、source_path/source_locator、会话追溯和待核对状态。外部拆卡说明更新为 instruction_version=5，导出仍预览并另存版本。

旧文件不需要转换就能获得干净阅读效果。如果希望统一文件格式，打开或聚焦那张卡，执行“迁移当前卡片元信息（预览）”：

1. 查看完整修改前后内容；取消不会写入文件。
2. 确认后先保存原文件完整备份到 `Carddesk/backups/metadata/<唯一标识>.md.bak`，再核对版本并转换当前文件。
3. 原有身份属性与注释保留，三行内容移动为 sources 数组、raw 字符串、updated 日期字符串。已有同名属性、非标准三行、无效 YAML 或文件变化会拒绝转换，需重新预览或手动处理。
4. 备份使用 .bak，避免重复 card_id 被当成另一张卡。需要恢复时先核对当前修改，将备份正文复制回原笔记；不要直接将备份改成另一张 .md 卡片。

没有批量自动转换。确认后的转换若遇到晚到的文件修改，会保留完整备份并报告，不能用旧预览覆盖新内容。索引工具仍需要按其说明 refresh；阅读隐藏不等于改变实际索引内容。

## 原地编辑与草稿恢复

卡片内编辑提供纯 Markdown 文本，不包含 Obsidian 原生编辑器的自动补全、富文本和附件拖拽。可以点击“完成”或 Cmd/Ctrl+S 保存；子卡仍可保留。编辑中先保存或取消，再点击这张卡的“与 Agent 讨论”，聊天只发送已保存的文件内容。

修改约 250 毫秒后保存为本地草稿，保存正文前也先落盘草稿；正常收起或关闭会保存最新文本。通过命令“恢复未保存的卡片编辑”选择草稿继续；若草稿已经在某个阅读页编辑，只聚焦该编辑器。原卡缺失时可查看和复制草稿，先恢复文件或手动另存。突然崩溃仍可能丢失最后未落盘的一小段输入。

草稿保存在插件 data.json 的可选 drafts 字段，含路径、基准原文及编辑内容，最多 20 份；单份原文/内容各最多 1000000 字符，超过约 1 MiB 的文件建议在原生编辑器处理。阅读路径与聊天仍共用同一串行存储。旧构建回退前须备份 data.json，旧版保存会忽略并丢弃新增草稿字段。草稿与实际笔记同样属于私有内容，不进入仓库或发布包。

如果笔记在其他位置被修改、移动或删除，保存会拒绝覆盖，编辑框与草稿仍保留。可复制草稿与最新原文核对，或取消后重新打开编辑；不会自动合并冲突。取消只丢弃草稿，不改原笔记。

## 导出说明 v5

更新插件后重新执行“导出 Agent 说明”，为本次任务核对原文/新卡/允许/排除目录。v5 的拆卡及 manifest 示例使用这些目录；实际批次、来源定位和日期仍须填写。本次明确给过的授权不需要再次逐条批准，未授权的旧卡改写仍先报告。

已有文件有差异时另存 `.v5-N.md`，内容相同时复用。把导出成功后显示的实际路径交给外部 Agent；无后缀旧文件不会被自动替换。检索工具在外部准备，不再假定特定电脑的 Node 路径、模型或测试索引。插件聊天、原地编辑和阅读交互保持原样。

## 侧栏界面

顶部“讨论对象”始终标明当前会话围绕的卡片，与中间阅读页可以不同。会话下拉框切换历史，新对话创建独立记录；“更多”包含发送说明和需确认的删除操作。卡片完整路径可在讨论对象或附带卡片名称上悬停查看。

消息区独立滚动，底部输入框保持可见。位于消息底部时跟随新回复；向上阅读历史时保留位置。空会话提供提问建议，点击只填入输入框，可编辑后再发送。输入为空时发送不可用；回复中发送按钮变为“停止”，中断或失败后可重试。

“附带卡片”显示已选数量，可展开勾选和预览；消息中的“参考”记录该次实际发送的卡片。聊天回复下的“整理为关联卡片”仍先选取内容，再生成预览，确认后才写入。

## 原生编辑入口

点击卡片铅笔进入原地编辑，操作栏位于输入框上方：“原生打开 / 取消 / 完成”。输入框沿用笔记正文字体，支持完整 Markdown 和顶部属性；仍是轻量文本输入，不包含原生自动补全和富文本功能。

“原生打开”会先保存当前内容并检查版本，成功后在新标签页打开对应文件的原生编辑视图。原接页阅读标签和已展开分支保留；可切回继续阅读。若存在外部修改冲突或保存失败，保留原地输入及草稿，不打开原生页。原生页打开失败时，已保存的笔记仍保留，会显示错误提示。
