# 0.4.0 验证与交付验收

日期：2026-11-25。范围：本地 Codex 聊天到关联卡片的小范围交付。不是模型质量、规模性能或多平台认证。

## 环境与范围

macOS / Obsidian 1.9.14 / Codex CLI 0.169.0-alpha.11.1。使用既有独立测试库，先本地备份原插件程序和 data.json；仅将原创渐进式披露短笔记发送给模型，不发送原有私有书籍或笔记。

Codex App Server 接入依据：本机 CLI 帮助、生成的 JSON Schema，以及 [官方 App Server 文档](https://developers.openai.com/codex/app-server/)。配置结构另对照 [官方 config schema](https://github.com/openai/codex/blob/main/codex-rs/core/config.schema.json)。本实现按实际安装版本验证，不宣称任意 CLI 兼容。

## 真实模型和宿主

- 临时目录和临时只读线程完成握手；实际适配层收到中文完整回复及 66 次增量事件。
- Obsidian 设置页保存本机 Codex 路径与测试输出目录；原有阅读路径未被设置写入覆盖。
- 从原创笔记发起问题，只附带该笔记，获得真实中文解释及边界判断。
- 选取回复，第二次真实模型请求整理出标题、正文和自然语言链接文字。
- 草稿预览显示新卡与原卡追加链接；确认后创建 Markdown，含待核对、会话和消息追溯字段。
- 新内链在原有接页视图原地展开；返回上层保留分支，收起正常，重新展开后保存两节点命名路径。
- 重新加载应用后，聊天、当前会话、展开树与新卡焦点恢复。
- 再次发送原创测试问题后点击停止，显示中断与重试入口，不把中断回复当完整消息。
- 完整退出 Obsidian 再启动，完整聊天及中断状态仍在，两节点阅读树和新卡焦点恢复。

真实模型生成结果只保留在本地测试库，不随源码、示例或开发包提交。上述测试不替代独立人工内容审阅。

## 仍有限制

暂不执行混合优化、独立材料评审与千卡/万卡测试。没有发布或合并 main，GitHub Release 仍为 0.3.4。
