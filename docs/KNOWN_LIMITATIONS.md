# 接页 Carddesk 0.4.0：已知限制

0.4.0 已通过本机交付验收，以 GitHub 预发布版供独立库试用；尚未上架社区市场。

- 平台：在 macOS / Obsidian 1.9.14 实测，最低声明 1.8.7。Windows、Linux、移动端未完成验证，尚未上架社区市场。
- Codex：仅验证 CLI 0.169.0-alpha.11.1 的 app-server stdio 协议，其他版本不保证兼容。复用本地 auth.json 登录，不加载用户 config.toml 的自定义模型提供商、MCP、插件和钩子。非文件凭据存储、Windows 符号链接权限未验证。
- 模型：聊天和草稿整理通常调用远端模型服务，使用账户额度；所选正文与会话历史会发送。阅读不需要 CLI、网络或模型。不支持 Claude Code、多 Agent、工具调用或自主检索。
- 转卡：完整回复经选取和整理后，每条回复最多一张卡；文件名使用消息身份，正文标题可编辑。只在提问卡末尾追加链接，不自动选择段落或替换已有关系。卡片标记“对话补充，待核对”，不作为来源已核实的事实。
- 跨文件操作：新卡创建和原卡加链没有全局事务。原卡变化拒绝写入、目标不同内容不覆盖；部分失败保留新卡后可重试。历史聊天的原卡路径不会随文件移动自动迁移。
- 聊天：完整回答渲染 Markdown，流式阶段按文本显示；模型给出的代码块不启用查询/插件代码处理器、图片和嵌入不自动加载；没有附件、消息编辑、自动总结或跨设备会话同步。最多 20 个会话、每会话 80 条消息，单问题 10000、单回复 40000、单上下文卡 60000 字符；最多 8 张上下文卡、单次重放 160000 字符，聊天 JSON 总计约 2000000 字符。超限报错，不静默截断。突然崩溃可能损失最近未落盘的一小段流式文本。
- 数据：配置、聊天和阅读共用插件 data.json。升级前备份；0.3.4 阅读快照 v1 可读。降回旧版保存时会移除聊天字段，回退前另存 0.4.0 状态及编辑草稿。损坏或未知版本阻止覆盖。
- 阅读：保持现有 P0 布局与交互，阅读树最多 100 节点，不提供块级/附件卡片展开。原生编辑器链接行为不变；精确像素滚动位置不保存。
- 检索：原项目的独立外部配套，不包含在本插件。其 Node 22+、QMD、模型和显式 refresh 需求继续存在；聊天不会自动运行它。允许/排除目录不代替操作系统权限。
- 验证：独立来源与第二评审、千卡/万卡性能、进一步混合检索优化继续暂缓；不能把工程测试和原创小样例当作质量或规模认证。

公开包只包含程序、通用文档和原创示例；不含用户书籍/PDF、私人笔记、聊天或阅读状态、实际本地配置、编辑草稿、评测数据、密钥、依赖缓存或模型权重。完整操作见 [聊天指南](CHAT_GUIDE.md)。

- 逐卡编辑现为卡片内的纯 Markdown 编辑框，支持完成保存、取消和草稿恢复；原生打开先保存并检查版本，再开新标签，冲突时保留原地草稿，不含原生编辑器的自动补全、富文本或附件拖拽。元信息隐藏只作用于接页阅读；旧正文只识别标题后连续完整的 Sources/Raw/Updated 三行，不隐藏任意引用。单卡迁移需预览确认，已有同名属性或歧义会拒绝；先保留 .md.bak 完整备份，不批量转换。备份和原卡是本地用户数据，不进入公开包。

## 0.5.0 开发构建补充

内置任务仅支持 Vault 内 Markdown/TXT 或粘贴，单篇30000字符、60片段，单行5000字符；最多10个主题、30张卡，每批1～10张。已有卡片关键词范围最多500个文件，每候选全文最多12000字符，过大文件明确列出；每次模型关系检查最多8对。没有向量数据库或自动全库索引。任务和原文快照属于用户数据，须随 Vault 备份。部分写入保留已完成文件，不能在写入阶段改计划。文件名使用稳定卡片编号；质量和规模测试仍不在本轮范围。
