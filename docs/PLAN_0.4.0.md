# 0.4.0：卡片聊天与关联补充

更新：2026-11-25。分支：codex/v0.4.0-agent-workflow。基线：0.3.4。

用户已批准把版本主线从“复制外部 Agent 任务”改为“当前卡片 → 聊天 → 草稿 → 确认关联新卡”。当前为已实现并完成本机小范围验收的开发构建，未发布 Release。

## 交付范围

- 首版只接本机 Codex CLI；右侧聊天，不改变现有阅读布局、展开/收起和返回上层行为。
- 默认附带当前卡片，可从已展开卡片中明确选择额外上下文；发送前可查看正文。历史与所选正文交给 Codex 模型服务，不宣称离线模型。
- 流式回复、停止、失败重试、本地会话保存/恢复；读写与旧阅读数据共用串行存储。
- 选取回复并整理为一张独立草稿；可编辑、预览；确认后创建带追溯身份及待核对标记的 Markdown，并在提问卡末尾追加内链。
- 处理源卡变化、目标冲突、部分写入失败和重复确认。插件负责写入，Agent 不获得 Vault 工作目录，不自主运行工具。

## 已执行顺序

1. 技术验证：本机 CLI 帮助与协议、临时会话、真实中文流式回复；识别并修复配置字段类型错误。
2. 聊天：设置、上下文、消息状态、生命周期、存储兼容与边界测试。
3. 转卡：模型整理、编辑预览、追溯字段、版本检查、幂等及失败保留重试。
4. 集成：工程回归、独立 Obsidian 测试库的真实聊天转卡、原地展开、收起返回、保存与完整退出重启恢复；更新手册与开发包。

验证结果见 [开发版验证](VALIDATION_0.4.0.md)，每轮测试和优化见 [决策日志](TEST_OPTIMIZATION_LOG.md)。

## 后续顺序

1. 用户在独立测试库试用当前闭环，收集上下文选择、转卡内容和阅读连续性反馈；修复明确问题。
2. 如需公开交付，按用户指令完成 0.4.0 Release；当前只在开发分支交付代码和本地构建包，不自动合并 main。
3. 再决定是否加入第二种 Agent、Markdown 聊天渲染、可读文件名、更多来源/关联方式。

原计划中的外部任务复制、导出目录记忆、卡片包校验 UI 增强后移，不作为已实现能力；现有导出及校验功能继续保留。混合检索优化、独立材料/第二评审、千卡/万卡测试继续暂缓。图谱、批量自动拆卡、自主改链、市场和多平台支持另行规划。

## 本版边界

本机支持证明不等于所有 Codex CLI 版本兼容；对话补充不等于事实验证；工程和小样例流程不等于质量或规模认证。旧版回退会丢弃聊天字段，操作前须单独备份 data.json。
