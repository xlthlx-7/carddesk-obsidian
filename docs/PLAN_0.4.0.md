# 0.4.0 开发计划：本地 Agent 协作流程

日期：2026-11-25。状态：计划已建立，功能尚未开始实现。
基线：0.3.4 / cc8a1a00c059c0c86072a3d8a25b25aff7ce12c7。
开发分支：`codex/v0.4.0-agent-workflow`。

## 目标与范围

让用户在不接 AI 的情况下，更容易完成“配置目录 → 导出说明 → 复制任务给本地 Agent → 校验卡片包 → 渐进阅读”的完整流程。成功标准是减少用户手写路径和组织任务的步骤，而非增加阅读器功能。

保持 P0 嵌套布局、内链展开、多分支、收起、返回上层、现有命令和阅读路径行为。配置与任务操作放在设置页、现有导出弹窗和命令面板，不增加阅读视图顶部按钮。

不纳入：生成 API、内置聊天、启动 Codex/Claude Code、自动修改关联、向量数据库自研、检索工具迁入插件、图谱视图、块级展开、市场上架或移动端支持。此前暂缓的三项任务继续暂缓。

## 当前代码依据

- `src/agent-tools.ts` 的 InstructionModal 每次初始化为 Sources/Cards，未保存用户配置；导出结果只展示路径。
- `src/agent-instructions.ts` 返回默认文件路径；exportNew 可能另存版本，任务必须使用其实际返回路径。
- `resources/agent/retrieval.md` 仍含原项目目录和本机示例路径；独立插件需要消除这种隐含安装假设。
- 校验结果是一次性的 Modal；本轮对已读文件检查 mtime，但这不证明整包在完成后持续有效，更不证明 Obsidian 元数据已与当前正文同步。
- PathStore 当前独占 saveData，只序列化阅读字段。新增设置不能再建立一个独立 saveData 写入方，否则会相互覆盖。

## M1：配置持久化与数据兼容（先做）

- 增加设置页：原文目录、新卡目录、允许/排除目录；继续沿用安全 Vault 相对路径与排除优先规则。
- 可选保存外部检索工具项目路径，仅用于生成说明，不探测磁盘、不执行程序。未配置时明确提示外部工具未配置，仍可使用文件关键词搜索和全部阅读能力。
- 建立统一数据存储入口，串行写入阅读状态与设置；禁止两个模块分别覆盖 saveData。
- 保持旧 PathData v1、Snapshot v1 可读取，优先以可选设置字段向后兼容；若实现需要改 schema，必须先说明迁移及回退方案，不直接升版本覆盖旧数据。
- 配置字段异常与阅读数据损坏分开处理；未知数据版本继续阻止覆盖。数据模型加入设置后的旧版回退行为需明确说明。

验收：从 0.3.4 数据升级后，自动进度、命名路径、顺序与焦点不变；配置保存与阅读进度并发更新不丢数据；重启配置仍在；保存失败明确提示且可重试；取消弹窗不提交设置。

## M2：生成 Agent 任务说明（依赖 M1）

- 导出成功后提供“复制拆卡任务”和“复制关联检查任务”，另提供可选择的文本，剪贴板失败仍可手工复制。
- 拆卡任务选择具体原文文件和新输出目录；关联检查选择当前卡片或指定包。缺少必要输入时不生成假定路径。
- 使用实际导出的三份路径，包括 .vN-N 另存路径；导出失败或部分成功时不宣称任务已就绪。
- 拆卡模板要求先读说明、处理指定来源、生成独立卡片与 manifest；关联模板要求提出问题、检索、阅读全文核对、只写建议报告，批准前不改旧卡。
- 外部工具路径采用结构化字段或明确文本展示，不拼接可执行 shell；不默认 /usr/local/bin/node 或开发者机器路径。
- 更新三份内置说明，清除本机状态目录假设，统一插件/工具边界。说明内容改变时提升 instruction_version，保留 protocol_version=1 与不覆盖已有文件的规则。
- 不自动把 Vault 绝对路径写入共享说明；用户在 Agent 侧指定本地 Vault。任何可选绝对路径持久化都须说明只存在插件设置中。

验收：中文/空格路径正确；新版另存后任务引用实际文件；未装检索工具也能完成任务说明与拆卡校验；全部模板不得自动运行程序、授予权限或批准加链。

## M3：卡片包校验反馈（依赖 M2）

- 校验期间显示进行中状态并防止同一次操作重复提交；错误与警告仍分开，保持只读。
- 在结果中增加“重新检查”；显示结果对应的检查时间，提示结果不是内容正确性的认证。
- 校验期间包内卡片、来源或 manifest 变化时，将结果标记为需重新检查；元数据未同步时等待或明确要求重试，不展示虚假成功。
- 点击“以接页打开入口”前重新检查包；新检查失败或有错误时保留报告，不打开入口。警告沿用允许打开的规则。
- 窗口关闭后异步任务不得更新已销毁界面；重复检查不能用旧结果覆盖新结果。变化监听和组件须随窗口关闭释放。
- 本版不加入报告持久化、自动修复、包扫描服务或关联自动执行。

验收：合法、非法、缺文件、重复 ID、元数据延迟均有明确反馈；检查中修改/改名/删除，及报告打开后再修改，都不会把旧成功当作当前成功；重新检查可恢复；校验不写入卡片。

## M4：集成验收与发布准备（最后做）

- 现有 24 项回归全部通过；新增测试覆盖存储兼容与并发、任务实际路径、校验过期与异步生命周期，不为静态文档堆叠测试。
- 独立 Obsidian 测试库实测：从 0.3.4 升级 → 保存设置 → 导出说明 → 复制任务 → 使用原创小材料验证文件协作 → 校验 → 多分支阅读 → 命名保存 → 退出重启恢复。
- 原创演示仅证明文件流程；未实际调用 Agent 时，必须标记为人工准备，不能称为模型拆卡质量验证。
- 再核对 Cmd/Ctrl 点击、附件/标题/缺失链接的宿主行为与旧布局不变；检查既有笔记及 data.json 备份、升级和回退操作。
- 更新安装说明、限制和操作手册。通过验收后统一提升 package.json、package-lock.json 与 manifest.json 到 0.4.0；计划分支建立时暂不更改运行版本。
- 形成插件/原创示例包与校验清单。公开包不得包含测试库状态、用户材料、评测数据、外部工具路径或模型。发布到 GitHub Release 另按用户指令执行。

退出条件：工程测试与真实宿主验收均通过，无未解决的数据丢失/旧结果误判问题；有明确升级和回退说明。CI 通过不能代替真实 Obsidian 验证。

## 顺序与工作量

按 M1 → M2 → M3 → M4 串行推进，每阶段独立提交并更新待办与测试决策日志。M1、M3 为主要风险点，不穿插新增阅读布局。

粗估：M1 1～2 个开发日，M2 1 个，M3 1～2 个，M4 1 个，总计 4～6 个开发日；这是工作量估计而非日期承诺。若范围超出估计，优先保证配置、任务交接与数据保护，延后非必要的校验界面增强。

## 后续暂缓

- 混合检索进一步优化：保留在外部工具项目，不纳入本版。
- 独立材料与第二评审：尚未完成，不以原创样例流程替代。
- 千卡/万卡性能测试：尚未完成，不承诺大库性能。
- 社区市场、更多平台：需要另行确定范围与验收，不自动进入 0.4.0。
