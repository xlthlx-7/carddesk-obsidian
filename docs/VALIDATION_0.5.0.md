## 真实 Obsidian 与模型

macOS / Obsidian 1.9.14，复用已验证的本机 Codex app-server 接入。先在独立 test-vault 备份 0.4.0 程序和 data.json，再安装 0.5.0 开发构建。只使用新增原创材料和原创已有卡目录。

1. 从“拆成知识卡片”导入 Acceptance/内置拆卡材料.md，原文为 261 个字符，拆成三个来源片段。
2. 在插件内填写整理重点与已有卡片目录。模型给出一个主题、两张卡的结构建议，覆盖全部片段。
3. 确认生成批次，得到两张独立草稿，来源分别为片段1及片段2/3。
4. 本地关键词检索仅搜索 Acceptance/已有卡片，找到两组候选；选择后送模型检查。
5. 首轮检查因无关系/重复结果缺少链接文字触发过严校验；修复为只有真正采用的关系需要入口文字。关闭并重启宿主，按任务标题恢复原任务，草稿、结构和候选选择仍在，无需重做批次。
6. 重试得到一条补充解释和一条重复关系；显式采用前者，选择复用旧卡处理后者。
7. 预览显示只创建三个文件：一张新卡、一个入口、一份清单。确认后任务完成，原文和旧卡均未改写。
8. 点击任务中的阅读入口，新卡原地展开，再沿关联展开已有来源核对卡，形成三层阅读结构。

总共进行了四次真实模型请求（结构、批次、首次关系检查、修复后的关系重试）；不推算或声称已测得固定 token 成本。实际模型取消与多批续跑由自动化覆盖，本轮宿主验证的是保存后重启恢复和同批关系重试。

## 发现与修复

- 候选勾选后刷新导致滚动位置改变：保留任务滚动位置与带稳定键的展开面板，增加回归，宿主后续勾选保持位置。
- 无关系/重复不该强制发明链接文字：调整提示、解析和校验；未验证的半批关系不应用。
- 完成态重复关系误显示 undefined：分离只读重复展示与可采用关系控件，增加完成态界面测试。
- 补齐生成批次来源覆盖与引用式 Markdown 链接约束，防止结构已覆盖而卡片明显漏片段，以及清单图与实际链接不一致。
