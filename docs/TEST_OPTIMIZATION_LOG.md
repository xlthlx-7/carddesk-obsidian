- 决策：优先改善配置、任务交接和校验反馈，保持阅读布局与交互；不接 AI，不自动执行关联，不恢复三项暂缓任务。
- 内容：创建 codex/v0.4.0-agent-workflow，加入开发计划及待办。运行版本仍为 0.3.4。
- 核对：阅读当前配置、导出、校验与存储代码，识别 saveData 单写入入口和实际另存路径作为实现前提。仅文档变更，不重复运行功能测试。
- 结果：计划已建立；M1～M4 尚未实现和验收。后续每轮记录假设、测试方法、改动、结果、代价与下一步，失败记录保留。

## 002 · 2026-11-25 · 改为聊天转卡版本与技术验证

- 新方向：用户批准优先实现当前卡片提问、聊天、草稿确认、关联卡片的闭环；原计划的任务复制及校验界面增强不再作为本版主线。
- 决策：首版只接本机 Codex CLI app-server，使用临时工作目录与临时线程；由插件重放有界本地历史，只提供选中的正文。禁用命令、补丁、浏览器、应用和多 Agent 功能，拒绝额外权限及工具请求，不把 Vault 作为 Agent 工作目录。
- 验证：本机 Codex 0.169.0-alpha.11.1 握手和中文增量回复通过；适配实现首跑因 tools.update_plan 的配置类型错误退出，定位后改用 enabled 字段，不通过降低权限限制绕过。
- 结果：实际适配层原创中文问题返回完整回复与 66 次增量事件。该结果仅证明当前 CLI 的模型连接，不证明所有版本兼容。

## 003 · 2026-11-25 · 存储、并发与写卡失败测试

- 问题：新增聊天不能覆盖旧阅读数据；停止/关闭不能保留活跃子进程；创建卡片后加链失败不能造成重复或覆盖用户修改。
- 内容：沿用 PathStore 单写入队列，增加可选 agent 字段；重载 pending 转为 interrupted；实现流式 UTF-8 解码、取消和进程清理。草稿写入检查原卡版本，目标不同内容不覆盖，部分失败保留新卡并可原路径重试。
- 测试：旧 24 项回归通过；新增上下文与数据边界、旧版升级及并发保存、重复确认、源卡变化/目标冲突、部分失败重试、拆分 UTF-8、取消后重试、工具请求拒绝和启动错误，共 35 项全部通过。
- 优化：进一步检查发现发送前读取上下文存在准备阶段竞争，增加准备锁及关闭后检查，随后补做 UI 生命周期测试。
- 当前状态：0.4.0 开发构建安装到既有独立测试库前，已本地备份 0.3.4 程序与状态。仅使用原创短笔记，不把私有材料发送给模型；真实宿主闭环验证进行中。

## 004 · 2026-11-25 · 真实宿主闭环与最终边界回归

- 方法：在已备份的独立测试库中，仅用原创短笔记进行真实 Codex 问答及第二次草稿整理；点击确认写卡，再按既有阅读方式展开、返回、收起和命名保存。
- 结果：真实聊天 → 可编辑预览 → 待核对新卡 → 原卡末尾内链 → 原地展开通过。正常重载、完整退出后重新启动，聊天记录、停止后的中断状态、两节点展开树和新卡焦点均恢复；原有全部命名路径与备份逐项一致。
- 优化：补充流式文本约每秒保存；最后检查发现用户改过旧链接文字后可能再次追加同一消息的关系，增加固定消息标记冲突检查，要求手工核对而不重复追加。
- 工程结果：40/40 测试通过，TypeScript/esbuild 通过；阅读视图、阅读树、链接事件源码与 0.3.4 一致，旧 CSS 原字节前缀保留，新增规则只作用于聊天。
- 包结果：插件 ZIP 仅 3 个程序文件，示例 ZIP 37 个原创文件（新增聊天入口）；文档相对链接及归档成员范围核对通过，无私有材料、个人状态、登录文件或模型。
- 代价与边界：仅接当前本机 Codex CLI；新卡文件名保留固定消息身份；纯文本聊天；不加载用户自定义 CLI 配置；回退旧版前须单独备份聊天状态。继续暂缓混合优化、独立材料评审和规模测试。
- 后续：用户试用开发构建；仅修复明确问题，不自动合并 main 或发布 Release。实际模型生成内容与本地配置只留在独立测试库。

## 005 · 2026-11-25 · 逐卡编辑、讨论与元信息分离

- 用户方向：卡片右上角直接编辑、与 Agent 讨论；来源、原文入口和更新时间只在编辑时呈现。复用原生源码编辑器，不做内嵌编辑器，保持分支交互。
- 决策：编辑/讨论均以按钮所属节点为准，不读取另一个分支的焦点；阅读时只读过滤顶部 YAML，以及标题后完整且连续的 Sources/Raw/Updated 三行。普通引用和正文保留，不修改全局宿主设置。
- 迁移边界：新增单卡预览命令。仅识别明确的三行结构；顶部有同名字段或 YAML 无法无损合并时拒绝。确认后先备份完整文件为 .md.bak，再用版本比较写入，避免备份重复 card_id 进入 Markdown 索引。无后台或全库自动迁移。
- 新卡与说明：聊天新卡增加 sources/raw/updated 顶部属性，外部拆卡说明升为 v4，协议版本仍为 1；已存在说明继续另存，不覆盖。
- 方法：增加不同分支焦点下逐卡操作、原生源码状态、元信息隐藏与普通引用保留、迁移保留原 YAML 注释/身份/正文链接、字段冲突、精确备份与并发修改测试；随后用原创示例做真实宿主验证，不转换私有材料。
- 工程结果：47/47 项测试及类型构建通过。
- 宿主结果：独立库普通引用保留，元信息只读隐藏；点击编辑打开完整源码，原阅读标签保留。迁移原创示例后，顶部来源属性显示正常，普通引用与链接保留；完整 .md.bak 与原示例字节一致。子卡拥有焦点时，点击根卡讨论按钮，侧栏明确显示根卡路径；未发送任何本轮模型请求。
- 验证代价：本轮重载命令后宿主一度停在空白页，通过原生菜单正常退出并重新启动后恢复。工具对不明确坐标和重排后的旧元素编号分别拦截，随后改用新读取的明确控件定位完成操作；未绕过拦截、未动私有材料。
- 数据核对：既有命名路径和聊天会话与本轮备份一致；只转换新增原创示例，无全库迁移。开发包与远端 CI 继续作最终核对。
- 最终复核：仍为 47/47，TypeScript/esbuild 通过；插件 ZIP 3 个文件、原创示例 ZIP 38 个文件。相对文档链接、归档成员范围、阅读树与布局 CSS 不变均核对通过。备份、实际用户卡片和状态未进入归档。

## 006 · 2026-11-25 · 阅读卡片原地编辑

- 用户反馈：不希望编辑跳到原生源码标签，优先在阅读卡片内完成，右侧栏仅作为备选。
- 决策：卡片内切换完整 Markdown 编辑框，显式保存/取消；保持阅读子树挂载，元信息只在编辑文本中显示。首版不重造 Obsidian 自动补全、附件拖拽或富文本编辑。
- 数据保护：编辑开始保留基准原文，保存通过 Vault.process 比较版本；同步/外部修改、移动或删除时拒绝覆盖。草稿复用 PathStore 单写入队列，收起/关闭保留，提供恢复命令，取消才放弃草稿。恢复已打开草稿只聚焦现有编辑器，避免重复实例。
- 测试：第一轮 53 项全部通过，覆盖原地保存/取消、分支保留、完整属性、并发冲突、关闭读取竞争、草稿恢复及存储兼容。发现同一文件的 card_id 修改会被旧身份逻辑误判缺失，已修复同一存活文件的身份刷新并加回归。
- 进一步约束：编辑中的卡片先保存或取消再讨论，避免用户以为尚未保存的草稿已经发给 Agent。真实宿主仅使用原创示例，随后核对最终构建。
- 最终工程结果：54/54 测试和类型构建通过。原生标签编辑已被卡片内编辑替换，其他分支布局及元信息阅读规则保持。
- 宿主结果：原创元信息示例在原卡内显示完整 Markdown；保存验证句后原地恢复阅读，子卡保留。子卡输入未保存内容后收起，通过恢复命令找回一致文本；取消后笔记未被覆盖，草稿清空。
- 数据核对：既有命名路径及聊天会话与本轮备份一致；原始子卡与原创 fixture 字节一致；只有本地原创父卡写入一条验证句。没有模型请求或私有材料改写。
